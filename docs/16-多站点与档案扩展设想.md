# 多站点、文档簇与跨站协作（设想）

> **角色**：把尚未能安全落地的形状写成可回看的技术备忘。  
> **不是**：契约（[`08`](08-发现层对象模型.md)）、结构 ADR、下一刀清单（[`09`](09-v1.x-后续工作.md)）、本机 WIP。  
> **日期**：2026-08-16。对照 HEAD `9d75899` + 仓内 [`15`](15-系统评估与方向.md)。  
> **冲突时**：现行行为以 `08` + 代码为准；本文可以反对「现在就做」，但不能假装已经改了身份模型。  
> **读法**：§1 是约束；§2–§4 是形态；§5 是「现场能写/能做」；§6 是明确不做。过期后降为历史，不必现代化重写。

## 0. 这篇在记什么

公开站的产品形状已经比较清楚（终端探索、纸面阅读、HTTP 给 Agent）。新压力来自三件事，它们**都对**，但目前的机器面只支撑其中很小一块：

1. **cylf.me 要和其它站点关联**，而且要有中枢感，不能只剩 `https://` 清单。
2. **档案正文不能永远「一篇文件说完一个项目」**——磁盘上本来就有文件夹，人会自然写成一簇文档；现在身份模型把这件事禁止了。
3. **多站点之间要能互相调取、查阅、按需转发**（日程、健康、备忘可能住在别的站）。内置对话式 AI 和机械式脚本都是候选，但都还没有协议。

[`15`](15-系统评估与方向.md) 管的是「这个地方还可以成为什么」。本文管的是**地方与地方之间、文件与文件之间**——在壳还撑不住之前，先把形状钉在纸上，避免用半套功能换技术债。

## 1. 现行机器面（必须当硬约束）

| 层 | 现在实际是 | 对设想的含义 |
|----|------------|----------------|
| 身份 | `DocumentRef = { group, slug }`；`slug` 仅 `[a-z0-9_-]+`；`localKey` **恰好两段**（`projects/foo`） | **禁止** `content/projects/my_web/notes.md` 这种嵌套路径进发现层。磁盘「一个项目一个文件夹」与权威身份**尚未对齐**。 |
| 盘路径 | `content/<group>/<slug>.md`（`resolveContentPath`） | 文件夹结构存在于 Git，但不被 VFS / 写 API / Tab 当成目录。 |
| 发现 | `Item = source + localKey + kind`；首版 `source: local`，`kind: document` | 外源位已留（`09` §2.2 `github` 等），**没有**「另一个自己的站」这个源，也没有关系边。 |
| 人物链 | `person.json` → `links[]`；`about` 打成「链接:」 | 其它网站现在只能当 URL。没有房间、能力、可见性。 |
| 外链纸面 | `resources`（ADR 0008）：`url` + 自己的笔记 | **这是目前唯一「别的地方」的一等对象**，但仍是收藏，不是对等站点。 |
| 站内链 | 正文 `[x](/projects/foo)` 会过 `sanitizeProseHref`，变成**浏览器导航** | 不会 `open` 进阅读槽。图关系在纸面上是死链或跳出 Dual Phase。 |
| Agent | Bearer 写本地 document；无 webhook、无跨站令牌交换 | 人/Agent 已经能写**本仓**；不能合法地代表本站去写别的站。 |
| 禁区 | [`15`](15-系统评估与方向.md) §6：站内 AI 聊天 / 多文推理产品 | 跨站协作 ≠ 在 cylf.me 里做一个聊天机器人。 |

一句话：**中枢感目前只能靠叙事和 resources 假装；互调协议、文档树、跨站 AI 都还没有承重墙。**

## 2. 多站点：中枢感从哪来

### 2.1 不要一上来做的形状

- **只在 `person.links` 或 footer 堆 URL**：可行，零债，零中枢感。
- **把别的站 iframe 进阅读区**：破坏 Dual Phase，权限与 cookie 纠缠。
- **cylf.me 去爬、镜像、定时全量同步其它站**：立刻变成编排中心，和 `06`「富读中枢、外源后挂、先不做写编排中心」打架。
- **一个超级 Agent 拿齐所有站的写 token 住在本站前端**：0007/0010 明确禁止把写秘密放进浏览器。

### 2.2 建议的分层（由浅到深，可停在任意层）

**L0 — 地方卡（现在就能写内容）**

其它网站先作为 **`resources` 条目**（或将来一组专门的 document），纸面上写清：这是什么房间、谁可以进、本档案为什么要指向它、**不在本站呈现什么**。访客感到的中枢是「策月帘风的档案知道还有哪些地方」，不是「点开就进了另一个产品」。

终端侧暂不必新命令：`ls resources` / `open <slug>` 已经够用。`about` 继续可以列 URL，但**权威叙述应在纸面**，不在 JSON 清单。

**L1 — 地方作为发现条目（需拍板，未做）**

当「地方」稳定到不止三五个 URL 时，再考虑：

- 仍用 `kind: document` + tag（如 `place`），**不**新 kind；或
- 新 `source`（每个对等站一个命名空间）——这与 `09` §2.2 外源是同一类 Deep Dive，不要为「我的第二个站」另开一套身份。

索引里出现的是**可扫读的房间名**，详情仍是本仓写的导读 + 外链。本站**不**存对方的隐私正文。

**L2 — 只读调取（协议，未做）**

中枢要「可以查阅、按需转发」，最小协议应是 **Pull，不是 Mesh**：

1. 对等站若也暴露类似 `GET /api/v1` 能力表 + `GET /api/v1/items`，本站 Agent（本机或 CI，**不是**访客浏览器）按需拉一条。
2. 拉回的东西默认**不进**公开 snapshot。要公开，必须经过主人写成 `source: local` 的摘录（或将来 `source: <peer>` 且明确 `visibility`）。
3. 失败态允许 `planned` / 不可达；**禁止**为了目录好看而伪造对等条目（`08` §4 已有这句）。

健康、日程、备忘：数据面留在原站；本站最多存 **指针 + 一句为何相关 + 何时调过**。监控性质的行为（「今天该吃药 / 日程冲突」）属于**原站或本机 Agent 循环**，不是公开档案的气候层。

**L3 — 转发 / 互达（更后）**

「按需转发」拆成三种，不要混成一个 webhook 产品：

| 模式 | 谁发起 | 秘密在哪 | 适用 |
|------|--------|----------|------|
| **摘录粘贴** | 主人或本机 Agent | 无跨站写 | 现在；公开叙事 |
| **有向 Pull** | 本机 Agent 持有对方**只读**凭证 | 本机 env，不进仓、不进浏览器 | 查阅日程摘要 |
| **有向 Push** | 原站把「可公开事件」推到本站写 API | 本站已有 Bearer；对方只得 `thoughts/*` 一类窄 scope | 极少；要审计 |

对等 Push（两站互相写）在没有审计、过期、scope 之前不要做。`09` §3.3 的 webhook 仍是能力债，不是本设想的开口。

### 2.3 中枢感的 UI（设计约束，不是现在实现）

中枢感来自**同一套探索语言**，不是来自仪表盘：

- 终端可以说 `open places/health` 一类宾语（地方名），纸面打开导读。
- 需要真去对方站点时，明确「离开这座房子」，而不是假装还在 Dual Phase 里。
- 访客世界自洽（0010 / `15` §4.7）：看不到的地方保持沉默，不出现「登录后解锁 12 个站」。

## 3. 文档簇：一篇不够时怎么长

### 3.1 缺口

项目、思想都是延伸性的，却被压成单文件 stub。人会想「一个项目一个文件夹，里面多篇」。这在 Git 上完全自然；在 **DocumentRef / VFS / 写 API** 上是一次难逆的身份加宽。

未拍板前**不要**在盘上建 `content/projects/my_web/*.md` 然后指望 `open` / `edit` / HTTP 认它——写内核会当它不存在，Agent 会得到 `bad_request`。

### 3.2 三选一（方向已拍板）

| 方案 | 做法 | 代价 | 何时才值得 |
|------|------|------|------------|
| **A. 加宽路径（已选方向 · 2026-08-17）** | 允许 `localKey` 多段，`projects/my_web/log`；VFS 真目录；三组一律；含 mkdir/rmdir | 改 0001（或后继 ADR）、写路径、补全、单测 | 目标态；**已落地**（2026-08-17，[ADR 0013](adr/0013-document-ref-multi-segment.md)）；手测 [`docs/17`](17-嵌套DocumentRef手测.md) |
| **B. 集合对象** | 新 kind 或 frontmatter `members: []`，成员仍是扁平 slug | 发现层有边；阅读槽要会「打开集合」 | 关系比目录更重要时再议 |
| **C. 簇约定（过渡权宜）** | 身份不改；多篇扁平文件 + 共享 tag + 一篇入口 | 零契约债；`ls` 会变长 | **A 落地前**可用；非终态 |

> **校准（2026-08-17）**：内容协议场次收口——终端自由度要求与文件/文件夹同构，方向锁定 **A**；C 仅过渡。勿在发现层尚未认夹时建「假目录」。

**C 的写法（A 落地前权宜）：**

- 入口篇：`projects/<cluster>.md`（现状已是这样）。
- 延伸篇：`projects/<cluster>-<leaf>.md`，例如 `my_web-notes`、`my_web-log`。leaf 仍符合 `[a-z0-9_-]+`。
- 共享 tag：`cluster:<cluster>`（如 `cluster:my_web`）。现有索引已能 `?tag=` 过滤（`08` §5.3）。
- 入口篇用正文列出延伸篇的 **localKey**（给人和 Agent 读），不要依赖点击 `/projects/…` 进阅读槽——那条路径今天会跳出终端。
- 手写 vs Agent：用 tag `by:human` / `by:agent`（或正文一行声明）。**不要**先发明未进解析器的 frontmatter 键——PATCH 只认已文档化字段，私货键容易在部分更新时丢掉。

撰写身份值得将来进 `08`（可选 `origin: human | agent`），但在内容还是 stub 时，tag 已经够辨认。

### 3.3 内容不足（这是现在就能做的主业）

机器面缺口是「辨识」：哪些是 stub、哪些已经是可读世界。不必做 CMS。

可立即执行、且不改契约：

- 在入口篇 `status` 诚实写：`stub` / `笔记` / `可读`（自由文本；过滤已支持）。
- 延伸篇只写**一件事**（一次判断、一篇失败、一份接口备忘），不要再写总览。
- 公开长文优先 thoughts；项目簇优先过程与关系，而不是再写一份 WIP 清单。

这与 `15`「人还不是对象 / 冷访客内容不通」是同一缺口。扩展设想不能代替把一篇写厚。

## 4. 跨站 AI：内置模型还是机械传达

### 4.1 先定主语

cylf.me 上已经有两种合法智能：

- **访客**：读纸面、敲终端、拉公开 HTTP。不写。
- **主人侧 Agent**：Bearer + `If-Match` 写 `content/`。工作流在站外（Cursor / 本机脚本 / 其它仓的 Agent）。

「接入 AI 系统」若指在页面里聊天、多文推理、自动监控健康——那是新产品，且与 `15` §6 冲突。

「多站点协作很强」若指 **Agent 作为正式客人在几个站的 HTTP 之间搬运**——这与现架构同向，缺的是**对方站的契约**和**本机编排**，不是本站再嵌一个模型。

### 4.2 推荐默认：机械传达 + 站外模型

```text
[日程站 / 健康站 / 备忘站]  --只读 API 或导出-->  本机 Agent（可含大模型）
        |                                              |
        | 需要公开的叙事                                 | 需要进档案的摘录
        v                                              v
   仍留在原站                                      PUT cylf.me /api/v1/items
```

- **模型**住在本机或单独的 agent 运行时，不进公开前端。
- **本站**继续只暴露发现与写信封；不解释「今天该不该运动」。
- **脚本**（cron、手动）比「内置 AI」更可审计：谁拉了什么、写进了哪篇、hash 是什么。

内置模型只有在「对方站没有 API、又必须在浏览器里完成」时才值得重新讨论——那种情况通常说明对方还不该接入中枢。

### 4.3 最小互认（给以后的对等站抄）

对等站若要被本中枢调取，建议对齐这几件事（不必是 Next、不必抄 UI）：

1. 一份能力发现（有哪些 kind/source、是否允许匿名读）。
2. 条目身份稳定（`source + localKey` 或等价物），详情可拉正文或明确拒绝（隐私类返回 403 而不是空 200）。
3. 写面若存在：独立密钥、scope、乐观并发；**本站的 owner session 不得当对等站的凭证**。
4. 可见性三态在协议里就要有：`public` / `owner` / `never-mirror`。健康与日程默认 `never-mirror`。

本仓 `08` 已经是「本站这一侧」的模板。对等站可以更窄（只读、无写、无终端）。

## 5. 现在就能做 vs 必须先停在纸上

### 5.1 现场可做（不改身份、债可控）

| 动作 | 说明 |
|------|------|
| 按 §3.2-C 写延伸篇 | 扁平 slug + `cluster:` + `by:` tag；入口篇列 localKey |
| 把其它网站写成 `resources` | 一篇一站：URL + 自己的话 + 不在本站呈现什么 |
| 把 stub 标出来 | `status: stub`；先加厚 thoughts / 人物纸面，而不是新功能 |
| 真用写 API | 延伸篇可以由 Agent 写；人审 hash。这已经是「协作」，只是单站 |
| 遵守禁区 | 不嵌聊天、不镜像隐私站、不建嵌套目录当已支持 |

### 5.2 形状已有、仍要单独设计才许动代码

| 动作 | 为何不是「顺手」 |
|------|------------------|
| 正文站内链 → `open` 进阅读槽 | `15` §4.8 已点名；要改 MarkdownProse 与终端会话的耦合，需一小刀，不是协议 |
| `about` / 人物纸面不再像链接清单 | `15` §4.1；内容与排版，不是多站点协议 |
| 索引暴露 `created`/`updated` | `08` planned；牵动存量文件 |
| 外源 `source` | `09` §2.2；对等站与 GitHub 应共用这一 Deep Dive，不要先做「cylf 专用 mesh」 |

### 5.3 只许先留在本文（做了就是债）

- 嵌套 `DocumentRef` / 项目文件夹进 VFS
- 跨站 Push、webhook 总线、共享写 token
- 站内 AI 聊天、健康监控仪表盘、日程嵌入底栏
- 新 `kind: site` 空枚举
- 为「中枢感」做第二套非终端首页或站点地图产品

## 6. 否决（写下来以免下次重开）

- 用 iframe / 单页应用把所有网站揉进 cylf.me。
- 让公开 snapshot 全量下发对等站的健康/日程正文。
- 用 DocumentRef 吞掉跨站身份（0001 已否；跨源只进 Item）。
- 在 PATCH 文档化之前依赖未解析的 frontmatter 私货键。
- 把本文抄进 `09` 变成本周刀。选中某一层（例如站内链 `open`）时再单开 ADR 或改 `06` 一句。

## 7. 和其它文档的关系

- **`06`**：仍是富读中枢，外源后挂。本文的 L2/L3 是外源的一种，不是改产品句。
- **`08`**：对等协议应对齐信封，不在本文改字段。
- **`09` §2.2 / §3.3**：外源与 webhook 仍后置；本文只提供「对等站 vs GitHub」应走同一身份门的理由。
- **`15`**：地方内部的完成态（人物、纸面、气候、方言）。本文是地方之间的完成态。两边都不要收成最小刀。
- **ADR**：本节没有任何 Accepted 决策。要加宽 slug 或新 source 时再开编号。
