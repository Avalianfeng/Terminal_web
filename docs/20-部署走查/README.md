# 20-部署走查（技术向全流程）

> **目的**：以 [`docs/20-部署前自评清单`](../20-部署前自评清单.md) 为脊柱，做一轮**技术方式 / 功能实现**向的全流程走查——每站讲「为什么需要 → 解决什么 → 产物/机制」，结合真实代码与磁盘产物；边学边沉淀决策与后续行动。
> **不是**：产品设计重开、文档体系重建、无限顺清单。
> **角色**：本文档是**过程与决策记录**，不与仓内 docs 治理体系混用（决策编号用「学-xx」，与项目 D-xx 分开）。

## 工作方式（用户确认版）

- **清单当验收，修只修阻塞上线**：不修能否安全开门 → 写遗留继续勾；是「没这篇文/误推 private/生产当 dev」→ 当场修；会变新交互面 → 停。
- **优先收脏树**：先出可上线 commit（干净工作区），不边勾清单边无限改文件。
- **文档轻量化**：文档链接到已有文档 + 以核心目的为视角的必要信息，**不重写**大量已有内容；回复只点核心。
- **技术向学习**：用户会外部提问并输入总结，Agent 按笔记角度**如实记录**即可。
- **用户小改需求**：按原则记录（后续行动清单），**不实现**，记录清晰即可。
- **子 agent**：默认不派；用户点名才派。
- **密钥纪律**：明文口令/token/session 不进聊天与文档；verify/build/阶段 3 陪跑**另开一刀**。
