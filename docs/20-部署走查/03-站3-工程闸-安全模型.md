## 为什么需要

dev 和 production **行为不同**，不模拟生产就会踩 docs/20 附录 B 的经典错题：「dev 上能 edit → 生产一定也行」。分水岭是 `site-principal.ts` 里一行字符串比较：

```ts
// lib/archive/site-principal.ts
export function isLocalDevPosture(nodeEnv?: string): boolean {
  return (nodeEnv ?? process.env.NODE_ENV) !== "production";
}
// resolveSitePrincipal: sessionValid→owner(session)；否则 local-dev→implicit owner；否则 visitor
```

- `NODE_ENV !== production`（dev/`next dev`）→ **无 cookie 也是 owner**（implicit local-dev）——写盘随便开 
- production 无 cookie → **visitor**（只读）

## 机制层（两个核心文件）

**`site-principal.ts` — 三态判定**：`session` > `implicit-local-dev` > `none`。capabilities：`uiWrite = owner && !ARCHIVE_UI_WRITE kill`；`musicBff = owner`。

**`owner-session.ts` — 签名 cookie**：session = HMAC-SHA256 签名（payload `v1.{iat}.{exp}`，TTL 7 天），httpOnly + sameSite lax + secure(production)。关键一行：

```ts
// resolveSessionSecret: env 有就用；否则 production → null（谁都验证不过 → 全 visitor）
// local-dev → 固定常量 "local-dev-session-secret"
```

生产没配 `ARCHIVE_SESSION_SECRET` → secret=null → login cookie 永远验不过 → **全站只读**。这是**安全默认**（fail closed），代价是站不可写（见检查题 1）。

## env 四件套（各自防什么）

| env | 防什么 | 缺失后果 |
|-----|--------|---------|
| `ARCHIVE_OWNER_PASSWORD_HASH` | 防任何人 login 成 owner | 没人能 login → 全 visitor（只读） |
| `ARCHIVE_SESSION_SECRET` | 防伪造 owner cookie | production 验证不过 → 只读 |
| `ARCHIVE_PUBLIC_ORIGIN` | CORS 白名单（write-cors.ts，非 `*`） | 写 API 浏览器代发被拒 |
| `ARCHIVE_WRITE_TOKENS`（可选） | HTTP 轨 Bearer 鉴权（scope 限定） | 未配 → HTTP 写 401 |
| `ARCHIVE_UI_WRITE=false`（事故闸，0007 §7） | 即使 owner 也不能 UI 写 | 维护窗口只读展示 |

## 为什么 build + start、为什么无痕窗口

- `npm run build` 先行：`next start` 是生产模式，dev 与生产构建路径不同（docs/20 2.2）
- 无痕窗口：dev 期间可能种过 local-dev secret 签的 cookie，无痕/清 cookie 保证从 **visitor 姿态**开始（3.2）
