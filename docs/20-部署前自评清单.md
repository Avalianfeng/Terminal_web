# cylf.me 部署前自评清单

> **用途**：在真实上机前，按顺序自检「我是否理解每一环、本机能否先证伪」。  
> **不是**：一键部署脚本；密钥生成教程的重复粘贴。  
> **权威**：安全 `[adr/0007](adr/0007-security-deployment-posture.md)` · 身份 `[adr/0010](adr/0010-site-principal.md)` · 曲库 `[adr/0011](adr/0011-music-local-cache-public.md)` · 歌单 `[adr/0014](adr/0014-playlist-curation-vs-sync.md)` · 正文离仓 `[adr/0018](adr/0018-content-visibility-and-sync.md)` · 读权限 `[adr/0019](adr/0019-capability-zone-permission.md)` · 短 runbook `[13](13-cylf.me-部署.md)` · 现实序列 `[19](19-现实校验与执行序列.md)` §4.9  
> **VPS 实况**：本机中枢 `状态/主机/远程/VPS.md`；上机 SOP `D:\学习\VPS\docs\新项目上机SOP.md`（路径 A：Docker + Caddy + 灰云）

**用法**

- 从上到下勾；前一阶段未过关，**不要**跳后一阶段（尤其安全模拟未做就上 VPS）。
- 标 **🤖 Agent** 的项：另开会话让 Agent 跑命令/改仓内文件；本清单只写「要什么结果」。
- 标 **👤 本人** 的项：必须你亲手点浏览器、保存密钥、拍板。
- 标 **🖥 VPS** 的项：整段置后；本机全部绿后再开。

## 阶段 0 · 心智模型（先能画出来再动手）

> 目标：别人问你「这站怎么被攻破/怎么写盘」时，你能指到具体层，而不是只说「有 login」。



### 0.1 三层对象

- [x] 能区分 **Person（站点主人）** / **SitePrincipal（visitor|owner 浏览器会话）** / **DocumentRef（文档路径）** / **Bearer token（Agent HTTP 写）** 四者，且知道 **不能互相替代**（0010、0007、0005）。
- [x] 能画出数据流：本机 `content/`（public 子集自建同步上 VPS）→ 快照 → 终端/阅读面；`data/music/` → 访客气候；`.netease-cookie` → 仅 owner BFF（0018、0011、0009）。正文**不**经公开 Git。
- [x] 知道 **local-dev** 与 **public-production** 的差别：`NODE_ENV !== production` 时 implicit owner；生产未配 env 时全站 visitor（0010 §2）。



### 0.2 写面双轨

- [x] **UI 轨**：`edit` → Server Actions → `content-write.ts`；公网须 owner cookie；Actions **无 Bearer**（0005、0010）。
- [x] **HTTP 轨**：`PUT/PATCH/DELETE /api/v1/items`；**始终** Bearer + scope + 可选 `If-Match`（08 §5.7）。
- [x] 知道 `capabilities.write: true` 是 **有意暴露**给 Agent 的发现信号，不是漏洞（0007 §6）。



### 0.3 网络与主机（先理解，阶段 8 再核对 VPS）

- [ ] 灰云 DNS → 源站 IP 暴露；证书在 Caddy/LE，不在 Cloudflare 橙云（VPS SOP §0）。
- [ ] 业务容器 **不** `ports:` 映射公网；只进 Docker `proxy`，由 Caddy 反代（VPS SOP §0、§3）。
- [ ] 同机 sing-box 与 Caddy 端口分工：443/tcp 站点、443/udp HY2、8443/tcp Reality；部署时勿占、勿停 sing-box。

## 阶段 4 · 密钥与保管（生成在本机，使用在 VPS）

> 目标：四类秘密 **用途分离、轮换路径清楚、泄露面知道**。



### 4.1 清单


| 秘密                      | 生成                                             | 存哪                    | 泄露后果              | 轮换                          |
| ----------------------- | ---------------------------------------------- | --------------------- | ----------------- | --------------------------- |
| 主人口令哈希                  | `npm run owner:password`                       | VPS `.env`            | 网页改盘              | 重跑脚本 + 重启                   |
| Session secret          | 同上或单独随机 32+ 字节                                 | VPS `.env`            | 伪造 owner cookie   | 改 secret → **全 session 作废** |
| Write token **哈希** JSON | `npm run token:generate -- --scope thoughts/`* | VPS `.env`            | 按 scope 改 content | 删旧 hash，新 token             |
| 网易 `MUSIC_U`            | 浏览器导出                                          | VPS `.netease-cookie` | 滥用 BFF 拉流         | 换 cookie 文件                 |
| Cursor `CURSOR_API_KEY` | Cursor 账户                                      | VPS `~/.profile`      | 服务器上 agent 被滥用    | 轮换 API key                  |




### 4.2 自评

- [ ] **👤** 明文口令、明文 write token **从未**进 Git、进 issue、进聊天日志。
- [ ] **👤** 已为生产 **单独生成** session secret（不要与 dev `.env.local` 混用同值，除非刻意接受 dev cookie 可移植——一般不要）。
- [ ] **👤** write token scope 采用 **最小**（如 `thoughts/`*），非 `*`（否则 smoke 403 测不到，且泄露面更大）。
- [ ] **👤** 知道 `.env` 在 VPS 上应 `chmod 600`，且 **不进 compose 镜像**（`env_file` 挂载即可）。
- [ ] **👤** 已决定：是否在首 deploy 就设 `ARCHIVE_UI_WRITE=false`（极保守）还是正常 owner edit（默认）。

## 附录 B · 常见「自以为懂了」错题


| 误解                     | 事实                          |
| ---------------------- | --------------------------- |
| help 里没有 edit 就安全      | Actions 必须硬拒 visitor（0010）  |
| 写了 login 就等于 Agent 也能写 | Agent 只走 Bearer，与 cookie 无关 |
| Cloudflare 橙云更安全       | 本架构要求灰云 + Caddy LE（VPS SOP） |
| 把 write token 当登录贴浏览器  | 0010 Rejected；token 不应进前端   |
| sync 歌单进 content       | 0014：sync 只写 data           |
| dev 上能 edit → 生产一定也行   | 生产必须 env + login；先阶段 3 模拟   |
| CORS 收紧 = 写安全          | Bearer 才是写鉴权；CORS 减浏览器代发面   |
