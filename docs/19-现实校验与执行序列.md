## 2. 方法论修正（本文最重要的一节）

### 2.1 「时间换复杂度、迭代逼近完美」的前提

这个思路可用，但有一个目前**未满足**的前提：**每一轮迭代必须有外部反馈信号**。

当前迭代循环是闭合的：主人 ↔ AI ↔ 文档 ↔ 代码。没有访客、没有上线、没有真实 Agent 写入、没有第二个站。

**闭环迭代不会趋近完美，只会趋近自洽**——每轮让系统内部更一致、文档更精确、边界更清楚，但整体方向是否对，从未被检验。

### 2.2 替代原则（写进日常抽刀）

> **每一轮迭代必须关掉一个不确定性。**
> 不确定性 = 只有做了才知道答案的事（部署行为、性能拐点、访客观感、某能力是否真被使用）。
> 与之相对的是「关掉一个不自洽」——那是好事，但**不能连续做**，因为它不带来新信息。

这条原则会自动把 §4 的顺序排出来，也会自动把「再收口一次终端语义」排到后面。

### 2.3 已经出现的症状（判据，不是自责）

- [`16`](16-多站点与档案扩展设想.md)：151 行多站协作 L0–L3 协议，**第二个站不存在**。纸面成本可接受；一旦驱动代码即为纯负债。
- [ADR 0013](adr/0013-document-ref-multi-segment.md) 嵌套路径已落地，`content/` 里**一个簇都没有**。这一刀值不值，取决于未来三个月是否真那样写——现在无法判断，**不要再往上加深度**。
- `15` §4 列了 11 个「面」，每个都值得设计。全部为真，但没有一个能在闭环里被验证完成。

## 4. 执行序列（本地先修，开门最后）

> **纪律**：一次一条，每条独立可提交、可验收。**不要合并成一个大 PR。**
> 每条给出：为什么 / 改哪 / 完成样子 / 验收 / 不做什么。
> §4.1–§4.7 是本地修，§4.8–§4.9 是撞现实。

### 4.1 接 CI（最先做，成本最低）

- **为什么**：`verify` 单命令闸已存在，但只在想起来时跑。接上去后，「我是不是留下了脏东西」从焦虑变成机器答复。
- **改哪**：新建 `.github/workflows/verify.yml`；Node 版本对齐本机；`npm ci` + `npm run verify`。
- **完成样子**：push 与 PR 触发；红了能看出是 lint / tsc / 哪个套件。
- **验收**：故意改坏一个断言 → CI 红；改回 → 绿。
- **不做**：不接 `smoke:write-api`（需 token secret）、不接 Playwright（见 §4.4）、不加覆盖率门槛。

### 4.2 修 playlist 写盘边界（拍板后再改）

- **为什么**：`lib/music/playlist-store.ts` 的 `playlistsRoot` = `content/music/playlists/`，**被 Git 跟踪**；`music sync` 在启动时 + 每 30 分钟自动跑并 `writeFile`。即**应用正常运行会持续修改版本控制下的文件**。当前工作区 3 个 yaml 脏着（+32 行）非人为改动。`data/music/` 已 gitignore，`content/music/playlists/` 没有——这条边界画歪了。这正是「说不清哪里不干净」的具体来源。
- **先拍板（难逆，建议开 ADR 0014）**，三选一：

  | 方案 | 做法 | 代价 |
  |------|------|------|
  | A. 全部移出内容区 | 歌单 yaml 迁到 `data/music/playlists/`，随 0011 缓存一起 gitignore + 部署时同步 | 「哪些歌单公开」的策展意图也离开 Git，失去版本痕迹 |
  | B. 拆两层（推荐候选） | **策展意图**（公开哪些歌单、顺序、显示名）留 `content/`，**sync 产出的曲目清单**进 `data/` | 需改 yaml 结构与 `playlist-yaml.ts`，一次真改动 |
  | C. 不自动写 | 保留现路径，取消启动 / 定时自动 sync，只留显式 `music sync`，产物由人提交 | 零结构改动；但「档案随时间自动更新」的语感没了 |

- **完成样子**：正常跑站不产生 Git 脏面。
- **验收**：`npm run dev` 跑满 35 分钟（跨一次定时 sync）后 `git status --porcelain` 为空。
- **不做**：不顺手重构 music 域其它部分；不借机做冷库管理页（[0009](adr/0009-music-layer-netease-bff.md) 已否决）。

### 4.3 清理文档自洽（10 分钟）

- `adr/README.md` 的 0007 行仍写「上线闸门代码未落地」——已被 [0010](adr/0010-site-principal.md) 落地，`09` §3.4 已勾。`15` §4.11 点名为「地图的尊严」，至今未改。
- `06` §4.2 / `09` §4 仍写「不做多媒体播放器」，与 0009–0011 并存。按 `15` §7：改为承认**已落盘的气候层是档案的一部分**，播放器产品化仍不做。
- **不做**：不重写 `01`–`05`/`07` 过程稿（`09` §4 已明确）。

### 4.4 组件层最小冒烟（不做大重构）

- **为什么**：§3.2 的盲区必须有机器兜底，但**现在不是拆 1624 行组件的时候**——那属于 `15` §4.11「上帝组件拆除」，需要单独设计。
- **改哪**：引入 Playwright，只写 **3–5 条主路径**：① 加载 `/` 跑 `help`；② `open <slug>` 阅读面板出现并含正文；③ `edit <slug>` 打开编辑器 → 保存 → `cat` 一致；④ `login` 掩码提示符（不断言口令）；⑤ 窄屏 375px 截图存档（先只留证据，不断言）。
- **完成样子**：`npm run smoke:ui` 可跑；CI 暂**不**强制（先让它稳定几周）。
- **验收**：本机全绿；故意改坏 `open` 输出 → ②红。
- **不做**：不追求覆盖四份手测清单全部条目；不做视觉回归（像素比对）；不为测试重构组件。

### 4.5 首屏 payload 实验（产出是数据与决策，不是功能）

- **为什么**：`app/page.tsx` 下发 `ArchiveSnapshot.body`（全量正文）。13 篇时无感；`15` 说「档案加厚后会先于皮肤成为瓶颈」，但**没人知道拐点在哪**。这是纯未知，可量化。
- **怎么做**：临时 fixture 造 20 / 50 / 100 篇（每篇 2–5k 字）→ 量 RSC payload 体积与首屏可交互时间 → 记进本文附录或新开一节。
- **完成样子**：一句可引用的结论，例如「≥N 篇 / ≥M KB 时必须改懒加载」。
- **验收**：结论写下来；fixture **删除不入库**（AGENTS.md 内容层测试策略）。
- **不做**：**先不实现懒加载**。先拿数据，再决定是否值得改 snapshot 契约。

### 4.6 UI 真相源分层（不是「重新设计 UI」）

- **现状判断**：动效层其实**已经做对了**——`lib/archive/motion-spec.ts` 是真正的动效 token 层（语义命名、`prefers-reduced-motion` 降级、BGM 开合与阅读面板共享时长常量）。主人问的「约束好的方法」已经在用。
- **真正的问题**：`app/globals.css` **2190 行**单文件，同时住着 5 套主题（其中 3 套是 lab 实验色板）、工作区布局、终端壳、xterm、编辑器、BGM。生产样式与实验色板混居。
- **改哪**：拆三层——① tokens（变量、字号阶梯、间距）；② 主题（生产主调独立，lab 色板移出生产文件）；③ 组件样式按区块分文件。保持 [`04`](04-外区设计读法.md) 禁区不变。
- **完成样子**：改一个组件的样式不必在 2190 行里找；lab 色板可整体摘除而不影响生产。
- **验收**：`npm run build` 通过；五套主题在 `/themes` 与主页视觉无变化（截图对照）。
- **不做**：不引入 CSS-in-JS / 组件库；不改视觉；**不在这一刀做重设计**（重设计应在 §4.9 之后、有真实观感时再开）。

### 4.7 两个已知小债（顺手）

- 歌词 rAF 暂停时仍空转（`15` §4.6 / 中枢遗留）。
- ≤640px BGM 单行塞播控 + 歌词 + 列表 → 允许两行或整体沉入背景（`15` §4.2）。

### 4.8 真用一次写 API（决定项目定位的实验）

- **为什么**：这个站与普通个人主页的**唯一不可复制之处**，是它给 Agent 准备了正式入口（发现层 + 统一 Item + Bearer/scope + `If-Match` + 与人类 UI 共用写内核）。而这个能力**从未被真的用过**。smoke 跑通 ≠ 有工作流。
- **怎么做**：从站外（另一个仓的 Agent / 本机脚本，**不是**本仓 dev 会话）按 [`10`](10-agent-写API验收.md) 完整走一遍：发现 → 索引 → 详情取 hash → `If-Match` PUT 一篇真 thought → 人审。
- **完成样子**：`content/thoughts/` 多一篇**由 Agent 写、由人审过**的真文章。
- **判据（重要）**：用完之后**是否还想再用**。
  - 想 → 这就是主线，`15` §4.9「Agent 作为正式访客」值得继续投入。
  - 用一次就再想不起来 → 说明该能力是自娱自乐，**停止在它上面加深度**，回到普通档案 / 博客形态。
- **不做**：不为这次实验新增 API 能力（检索、分页、webhook 全部按 `09` §3.3 后置）。

### 4.9 开门：部署 cylf.me（最后一步，但必须真的做）

- **为什么**：`15` §4.10 —— 部署不是运维收尾，是这个系统第一次面对陌生人。§3.3 的整团未知只能靠它关掉。
- **前置**：至少一篇可读中文长文进 `thoughts/`（否则冷访客成功标准仍不成立）。这是内容功课，不是代码。
- **怎么做**：按 [`13`](13-cylf.me-部署.md) 配 env、同步 `data/music/`，跑 [`12`](12-站点身份手测.md) / [`14`](14-music-本地曲库手测.md)。
- **完成样子**：cylf.me 真的在线；一篇长文；一季气候；主人能 `login` 回来。
- **验收**：陌生浏览器（无 cookie、手机真机）走完「进站 → `help` → `open` → 读完 → 听见」。
- **不做**：不为上线补第二套首页 / 进场动画（`15` §6 禁区仍有效）。
