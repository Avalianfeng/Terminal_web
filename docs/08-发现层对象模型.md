## 1. 为何有本文

最小 v1.0 已完成纯文本呈现（A）、公开读 API（B）与鉴权写最小闭环（C，08-07）。

校准后的满意主锚是**富读中枢**：站作为可被丰富发现与读取的中心；外源（如 GitHub）与其它类型后挂。第一刀是**发现层先统一**——钉「一条可读物」长什么样，再谈契约形状落地与具体外源；写面随后按同一身份模型挂上（见 §5.7）。

本文锁**对象模型**与现行 HTTP 契约形状。旧版 `07` 已被替代，保留为历史。

## 2. 产品对齐（一句）

发现层对外呈现**统一条目**；首版基础类型只有 **`document`**。身份用 **`source` + `localKey`**（复合权威）。索引带可读摘要；详情在索引之上加正文。

---

## 3. 统一条目

### 3.1 索引（列表 / 发现扫读）

每条至少：

| 字段 | 必填 | 说明 |
|------|------|------|
| `source` | 是 | 来源命名空间；站内文档为 `local` |
| `localKey` | 是 | 源内稳定键；`local` 下 ≈ 现行 `path`（如 `thoughts/archive-system`） |
| `kind` | 是 | 首版仅允许 `"document"` |
| `href` | 是 | 跟随到详情的 URL（实现时定） |
| `title` | 是 | 扫目录可读 |
| `summary` | 否 | 可选摘要 |
| `status` | 否 | 可选；自由文本（如 `"活跃开发 (WIP)"`），2026-08-11 起提供 |
| `tags` | 否 | 可选；字符串数组，2026-08-11 起提供 |

**不进最小集**（可后加、可省略）：派生 `id` 字符串。

**身份权威**：`source` + `localKey`。若响应附带拼接 `id`，仅为便捷，**不是**唯一权威。

### 3.2 详情（跟随 `href`）

在索引字段之上，`kind: document` 增加：

| 字段 | 说明 |
|------|------|
| `body` | 正文 |
| `bodyFormat` | 如 `"markdown"`（与现行读 API 对齐） |
| `hash` | 文件内容 SHA-256（hex）；写回时经 `If-Match` 头携带（见 §5.7） |

### 3.3 与现站内容的映射（约定）

| 现站 | 发现层 |
|------|--------|
| `projects/*`、`thoughts/*` 文档 | `kind: "document"`，`source: "local"`，`localKey` = DocumentRef 投影 `group/slug`（如 `thoughts/archive-system`） |
| `person` | **暂不进**统一条目 |
| `timeline` | **暂不进**统一条目 |

## 4. 首版范围与明确后置

**首版只做**

- 统一条目形状（上表）
- 唯一 `kind`：`document`
- 站内 `source: "local"`

**明确暂不进入对象模型 / 条目列表**

- `person`
- `timeline` / `timeline_entry`
- 外源实体（GitHub 等）
- 复杂权限、编排中枢（鉴权写已按 §5.7 最小闭环落地）

**能力表预留（非条目）**

发现文档（未来演进的 discovery）可列出 planned 能力/源，例如：

```text
kinds:      document (available) | person | timeline | … (planned)
sources:    local (available) | github | … (planned)
write:      local documents (available, §5.7) | 复杂权限 (planned)
```

占位用 `status: "planned"` 即可；**不要**为未接入源伪造索引条目。

`GET /api/v1` 的 `capabilities.filters` 声明当前支持的索引过滤参数（`status` 精确 / `tag` 全匹配 / `fields` 投影）。

**索引基础设施 planned 项（2026-08-11 记录，避免重复评估）**

| 能力 | 卡点 | 触发时机 |
|------|------|----------|
| 分页 `?limit=` / `?offset=` + `total` | 响应 shape 变化（届时考虑 apiVersion bump） | 外源（github）条目数破百 |
| 排序（如按 `updated`） | 文档模型无时间戳字段 | 加 `created`/`updated` 元数据模型时（牵动 content 解析、写盘格式与存量文件迁移） |
| 全文检索 `?q=` | 即 docs/09 §3「HTTP 检索」 | Agent 扫读面不够用时 |
| 按 `status` 聚合统计 | 同上；可被「扫读 + 本地聚合」替代 | 有看板需求时 |

## 5. HTTP 契约形状

对象模型统一后，契约也统一为一条面（不并行双轨）。`07` 的旧端点已被替换。

### 5.1 端点表

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1` | 发现：版本、能力（kinds/sources）、资源表 |
| GET | `/api/v1/items` | 统一条目索引（支持 `?kind=` / `?source=` 过滤） |
| GET | `/api/v1/items?source=local&localKey=…` | 条目详情 |
| PUT | `/api/v1/items?source=local&localKey=…` | 创建/覆盖文档（鉴权，见 §5.7） |
| PATCH | `/api/v1/items?source=local&localKey=…` | 部分更新文档（鉴权，见 §5.8） |
| DELETE | `/api/v1/items?source=local&localKey=…` | 删除文档（鉴权，见 §5.7） |
| GET | `/api/v1/docs?path=…` | 旧 path 语法糖，映射到 `source=local&localKey=…`，返回相同 08 形状 |
| GET | `/api/v1/person` | 人物记录（永久旁路资源，不收进 items） |
| GET | `/api/v1/timeline` | 时间线（永久旁路资源，不收进 items） |

### 5.2 Envelope

成功：

```json
{
  "ok": true,
  "apiVersion": 1,
  "generatedAt": "<iso>",
  "data": {}
}
```

失败：

```json
{
  "ok": false,
  "apiVersion": 1,
  "error": "<code>",
  "message": "…"
}
```

错误码：`not_found`（404）、`bad_request`（400）、`method_not_allowed`（405）、`unauthorized`（401）、`forbidden`（403）、`conflict`（409）。

### 5.3 索引形状

`GET /api/v1/items` → `data.items[]`：

| 字段 | 必填 | 说明 |
|------|------|------|
| `source` | 是 | `"local"`（available）、`"github"`（planned） |
| `localKey` | 是 | 源内稳定键；local 下 ≈ 文件 path |
| `kind` | 是 | `"document"`（available）、`"image"` `"music"` `"video"`（planned） |
| `title` | 是 | 扫目录可读 |
| `summary` | 否 | 可选摘要 |
| `status` | 否 | 可选；自由文本精确值 |
| `tags` | 否 | 可选；字符串数组 |
| `href` | 是 | `GET /api/v1/items?source=local&localKey=…` |

**过滤参数（`GET /api/v1/items`）**

| 参数 | 可重复 | 语义 |
|------|--------|------|
| `kind` | 否 | 单值；未知值 → 400 |
| `source` | 否 | 单值；未知值 → 400 |
| `status` | 否 | 单值精确匹配（自由文本，不枚举）；重复出现 → 400 |
| `tag` | 是 | 多值 AND：文档 `tags` 须包含全部给定 tag（`?tag=a&tag=b`） |
| `fields` | 是 | 投影白名单（`source` `localKey` `kind` `title` `summary` `href` `status` `tags`）；逗号分隔或重复参数均可（并集）；非法字段名忽略 |

所有过滤参数可任意组合。分页/排序/统计按 §4 planned 表后置。

### 5.4 详情形状

索引字段 + `body`（markdown 正文）+ `bodyFormat`（固定 `"markdown"`）+ `hash`（文件内容 SHA-256，hex）。

不保留旧字段：`slug`、`path`。`status` / `tags` 自 2026-08-11 起在索引与详情提供（可选字段）。

### 5.5 校验规则

- `source` 和 `kind` 是校验枚举。未知值 → 400 `bad_request`，消息列出 available 值。
- `source` + `localKey` 同时提供 → 详情模式；均不提供 → 索引模式；单独 `localKey` → 400；单独 `source` → 按 `source` 过滤索引。
- 发现文档 `/api/v1` 列出 `kinds.available` / `kinds.planned` 和 `sources.available` / `sources.planned`。

### 5.6 与 `07` 的差异

| `07` 端点 | 处置 |
|-----------|------|
| `/api/v1/archive` | 移除，由 `/api/v1/items` 替代 |
| `/api/v1/docs?path=` | 保留为语法糖，返回 08 形状 |
| `/api/v1/docs/{slug}` | 移除（slug 不再存在于契约） |
| `/api/v1/person` | 保留不变（永久旁路资源） |
| `/api/v1/timeline` | 保留不变（永久旁路资源） |
| 旧字段 slug/path | 从契约移除 |
| 旧字段 status/tags | 08 移除后于 2026-08-11 重新提供（索引/详情可选字段，见 §3.1/§5.3） |

### 5.7 写契约（2026-08-07 落地，C 最小闭环）

写与读同面：`PUT` / `DELETE /api/v1/items?source=local&localKey=…`（`docs` 语法糖不扩写面）。

**鉴权**：`Authorization: Bearer <token>`。token 由 `npm run token:generate [--scope <scope>]` 生成，只存 SHA-256 哈希到 `.env.local`（`ARCHIVE_WRITE_TOKENS`）。

- 无 token / token 无效 → 401 `unauthorized`
- token 有效但 scope 不覆盖目标 `localKey` → 403 `forbidden`
- scope 模型：`*` 全权；`thoughts/*` 覆盖前缀下全部；`projects/foo` 精确单个

**PUT（upsert）**：body 为 JSON 对象：

```json
{
  "title": "必填字符串",
  "summary": "可选",
  "status": "可选",
  "tags": ["可选", "字符串数组"],
  "body": "可选 markdown 正文"
}
```

- `localKey` 必须形如 `projects/<slug>` / `thoughts/<slug>`（slug 限 `[a-z0-9_-]+`）
- 服务端序列化 frontmatter + body 写盘（原子写：tmp + rename），与终端 `edit` 同一真相源
- 新建 → 201；覆盖 → 200；响应 `data` 为完整落盘文档（§5.4 详情形状 + `created`，含 `hash` 供下次 If-Match）
- body 上限 1MB

**DELETE**：删除文档；不存在 → 404 `not_found`。

**乐观并发（If-Match）**：请求头 `If-Match: <hash>`（详情响应 `hash` 字段原样带回）。当前文件内容 SHA-256 不匹配，或文件不存在 → 409 `conflict`。不带该头 = 直接覆盖（upsert 语义）。

**示例**

```bash
# 读详情拿 hash
curl "http://localhost:3000/api/v1/items?source=local&localKey=thoughts/foo"

# 带 If-Match 更新
curl -X PUT "http://localhost:3000/api/v1/items?source=local&localKey=thoughts/foo" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -H "If-Match: $HASH" \
  -d '{"title":"新标题","body":"正文"}'

# 删除
curl -X DELETE "http://localhost:3000/api/v1/items?source=local&localKey=thoughts/foo" \
  -H "Authorization: Bearer $TOKEN"
```

**安全边界**：无鉴权不可写；组白名单 + slug 校验防路径穿越；frontmatter 由服务端序列化（写不坏存储格式）；token 哈希存储 + timing-safe 比较。

**全量 vs 部分（重要）**：`PUT` 是整份替换——body 省略的字段即被清除，且**契约外 frontmatter 字段被丢弃、字段顺序按白名单重排**；`PATCH`（§5.8）保留契约外字段与原顺序。Agent 若要保守改写全量文档（不丢未知字段），应走 `PATCH` 而非 `PUT` 重建。两方法都拒绝白名单外 body 键（400）。

## 5.8 部分更新契约（2026-08-11 落地）

`PATCH /api/v1/items?source=local&localKey=…`：只更新传入字段，其余保留。

**三态字段规则**（body 键：`title` `summary` `status` `tags` `body`）

| 形态 | 语义 |
|------|------|
| 省略 | 保留原值 |
| `null` / `""` / `[]`（tags） | 移除该字段；原字段不存在时是 no-op（静默通过，不报错） |
| 有值 | 覆盖为新值（tags 为字符串数组） |

- `title` 不可移除：`title: null` 或空串 → 400（title 是唯一必填字段）
- 空 body `{}` → 400；白名单外键 → 400（与 PUT 一致）
- 文档不存在 → 404（创建仍走 PUT）
- **响应**：200，`data` 为完整落盘文档（与详情同构）+ `created: false`，含新 `hash`——写回一次即可核对，无需再 GET
- `If-Match` 可选，语义与 PUT 相同（§5.7）；冲突 → 409，按「重读详情 → 合并 → 再 PATCH」收敛

**示例**

```bash
# 只改正文
curl -X PATCH "http://localhost:3000/api/v1/items?source=local&localKey=thoughts/foo" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"body":"新正文"}'

# 删除 status（原无 status 时也安全）
curl -X PATCH "http://localhost:3000/api/v1/items?source=local&localKey=thoughts/foo" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"status": null}'

# 清空 tags
curl -X PATCH "http://localhost:3000/api/v1/items?source=local&localKey=thoughts/foo" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"tags": []}'
```
