# 终端真实性评估：真 PTY vs 快照+盘状态

> **角色**：暂时的方向评估（2026-08-17）。回答「终端是不是只是模拟、能不能换成真实终端」。  
> **不是**：契约、结构 ADR。  
> **结论先行**：**不换 PTY**；已用「快照携带真实目录树」补上盘状态反映（提交 `7e1bb48`）；真实 shell 的**行为细节**值得继续借鉴（列 [`09`](09-v1.x-后续工作.md) §1.4 候选）。

## 1. 触发点（主人实测 2026-08-17）

`mkdir projects/my_web` 后在终端 `ls`/`tree` 看不到新目录，`cd` 进不去；感觉「终端只是模拟，不能真实反映项目文件夹的真实状态」。

实测暴露了两个独立缺陷，均已修复（`7e1bb48`）：

1. **mkdir 目标语义**：`projects/...` 组前缀在组内 cwd 下被当作相对路径拼接（`/projects` + `projects/my_web` → `/projects/projects/my_web`）。修复：组前缀与 `/` 前缀一律按绝对语义解析（与 `edit` 同规则）。
2. **VFS 只由文档推导**：空目录（无 `.md`）在盘上存在但快照不知道 → 终端不可见、不可 cd。修复：快照新增 `directories`（组内真实目录树，含空目录，realpath 包含校验），VFS 建树先插目录再合并文档（复合节点）。

## 2. 为什么「真 PTY」不是正确层级

把浏览器终端换成真实 shell（服务端 PTY，如 [node-pty + WebSocket](https://deepwiki.com/vercel-labs/wterm/1-overview)、[wterm](https://deepwiki.com/vercel-labs/wterm/9.4-local-shell-example-(websocket-+-node-pty))、[WebShell](https://github.com/SudevOP1/WebShell)、ttyd/wetty）能买到：真实 `cd/ls/tab`、真实文件系统、真实进程。

但本终端的对象**不是文件系统**：

| 现状对象 | 语义 | 真 PTY 能否表达 |
|----------|------|----------------|
| `/projects/my_web/log` | 档案 localKey（盘上是 `content/projects/my_web/log.md`） | 不能——shell 看到的是真实路径，档案抽象不成立 |
| `open <路径>` | 打开 React 阅读面板（纸面卡片） | 不能——shell 只能 cat/less |
| `edit <路径>` | 打开 React 全屏编辑器（server action 写盘） | 不能 |
| `music …` | 网易 BFF / 本地曲库副作用 | 不能 |
| visitor / owner 身份闸 | `login`、uiWrite 硬拒 | 需要额外一层网关 |

真 PTY 要么跑在**真实 content/ 目录**上（档案路径是 `content/...` 前缀，与终端显示的双重身份不一致，还暴露服务器文件系统），要么做一个**镜像盘**（把快照投影成虚拟根，bash 跑在受限沙箱里）——后者等于自己重写一遍 VFS，却换来了 shell 的进程/文件操作能力（本项目明确不做编排中枢、不做无鉴权写、不做通用 shell）。安全面（pty 逃逸、命令注入、资源占用）与 [0007](adr/0007-security-deployment-posture.md) 的公网写面最小化姿态冲突。

**结论：档案终端 = React 副作用 + 快照数据面，这个层级是对的；缺的只是「数据面反映盘状态」，已补。**

## 3. 已落地的「盘状态」机制

- 快照 `directories.{projects,thoughts,resources}`：组内真实目录相对路径（含空目录；realpath 包含校验 + 深度上限；非法段名跳过）。
- VFS 建树：目录节点先行（含空目录），文档节点并入（复合节点 = 入口篇 + 簇）。
- 写后刷新：`mkdirDir`/`rmdirDir` server action 带 `revalidatePath("/")`，组件 `router.refresh()`。
- 效果：`mkdir projects/foo` → `ls` 立即出现 `foo/`；`cd /projects/foo`（空目录）可用；`rmdir` 后消失；Tab 补全覆盖空目录（mkdir 到空目录内）。

## 4. 值得继续借鉴的真实 shell 行为（低设计成本，别一次做完）

| 行为 | 现状 | 候选 |
|------|------|------|
| 组前缀 = 绝对语义 | 已修（与 edit 同规则） | — |
| `~` 展开 | 无（提示符用 `~` 表示 cwd，是显示约定） | 维持显示约定即可，不引入家目录语义 |
| `cd -`（回上一目录） | 无 | 可选；`cd` 无参回组根/根已有 |
| `cd ..` / `.` | 已有（normalizePath） | — |
| 路径补全下钻 | 已有（cat 自动下钻、目录带 `/`） | — |
| `ls` 目录优先排序 | 已有（dirs-first + 名称序） | — |
| 错误消息 POSIX 风格 | 0012 已定 | 档案命令 sweep 仍后置 |
| 实时文件变更侦测（watch） | 无（写后 refresh；外部改盘需手动刷新页面） | 可选：焦点/轮询刷新；**有刚需再开** |

## 5. 明确不做（与 15/16 禁区一致）

- 内置通用 shell / 文件浏览器（编辑器、删除、移动、执行）。
- PTY 沙箱镜像盘（等同一套新 VFS + 网关，为「真实感」付安全债）。
- 文件监听热同步（写路径全走本系统，外部改盘是例外不是常态）。
