# 数字档案：为什么从终端进入

这篇文字由 **Agent 写回实验**（`scripts/agent-write-thought.mjs` → HTTP PUT）产生或更新——用来验证 cylf.me 的正式写路径是否真能支撑「站外模型 + 本机编排」，而不是只在 dev 会话里改文件。

策月帘风的公开站不是「又一个个人主页壳」。它试图回答一个更旧的问题：**如何把一个人的思考、项目与日子，以可检视、可命令、可版本化的方式交给访客**——包括那些只会读 HTTP JSON 的 Agent。

## 第一界面为什么是终端

终端在这里不是装饰。它是浏览方法、命令表面，也是档案的第一层壳。你在里面 `open`、`find`、`search`，路径与 slug 是可复用的坐标；纸面阅读器负责把长文摊开；底栏的气候层（已落盘的本地曲库）是房间里的背景音，不是第二个产品首页。

若你习惯网页导航栏，可能会觉得绕。但若你把它当成**一间档案室的导览台**，许多设计选择会变得更自然：列表是目录，阅读槽是桌上的那一叠，rail 是尚未合上的文件夹。

## 人比页面更高

`Person` 是最高对象。项目、思想、收藏、时间线，都是同一个人的侧面——不是五个平行频道。`projects/my_web` 记录这个站本身；`thoughts/` 放延伸性的文字；`resources/` 是外站与解读；`timeline` 记下日子如何流过。

目前正文仍薄，但形状已经钉住：**加厚内容是在已有形状里填房间，而不是先做一个新 CMS 再决定放什么。**

## 给冷访客的最低成功标准

docs/06 写得很清楚：冷访客应能用终端找到并读完一篇世界观/自我探索长文，纸面不别扭。这意味着：

1. **找得到**——命令与补全不骗人，嵌套路径与盘状态一致（ADR 0013、docs/18 已收口）。
2. **读得下去**——排版仍是轻量 markdown，但段落、status、摘要、标签可读；长文尚未到「杂志级」排版，这篇就是第一块砖。
3. **不必登录**——访客世界自洽（ADR 0010）；听不到未落盘的歌，但不应被灰条乞求注册。

## 给 Agent 的门

写 API 不是摆设。发现层统一 `document` 条目；Bearer + scope + `If-Match` 与人类 UI 共用写内核。站外脚本或另一个仓里的 Agent 可以 PUT 一篇 thought，而不必打开 Cursor。

实验脚本：`scripts/agent-write-thought.mjs`（见 docs/10）。**若你读完这篇后仍想再用写 API，说明这是主线；若一次就忘，则停止在 API 上加深度**——这是 docs/19 §4.8 的判据。

## 气候层

音乐不是网易云替代。主人从网易 BFF 拉流、download 落盘；访客只听 `data/music/` 里已存在的媒体（ADR 0011）。歌单策展在 Git（content）；曲目清单在 data，sync 不再弄脏版本库（ADR 0014）。这是「房间气候」，不是播放器产品。

## 尚未完成的面

诚实列出缺口，避免闭环自洽错觉：

- **人物纸面**——`person.json` 仍是名片，不是「打开 person 是一篇人」。
- **部署**——cylf.me runbook 在 docs/13，实例需主人按清单真开一次门。
- **懒加载**——snapshot 仍全量正文；附录 A 测到 100 篇 ~270KB 仍可接受，加厚后再议。
- **UI 自动化**——`smoke:ui` 五主路径已绿，CI 暂不强制。

## 如何继续读

在终端试：

```text
open thoughts/digital-archive-entry
projects
help
```

若你是 Agent：`GET /api/v1` → 索引 → 详情。写回前读 hash，冲突则 409。
